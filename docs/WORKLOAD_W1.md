# Verify Work: local transcript validation

W1 accepts a bounded Technocore `/export` JSONL file through the **localhost connector page**. Select **Import transcript locally** on `/technocore`, choose the room and file in the localhost window, then return to BLACKBOX and select **Validate locally**. The production-origin page receives only a safe descriptor/result; raw transcript bytes are never uploaded to Vercel. An import expires after ten minutes, at most four may be pending, and restart discards pending raw bytes. A completed local Flight Record persists only its public-safe artifact.

`VALID` means the supported signed rows **in the supplied bytes** passed required structural and cryptographic checks. `INVALID` means a decisive required check failed. `INDETERMINATE` means there is no decisive failure but the available signed evidence is insufficient or unsupported. `INPUT_REJECTED` and `INTERNAL_ERROR` are **not transcript verdicts**. All results disclose bounded history, possible gaps, unsigned venue metadata and an optional **supplied—not authenticated—generation header**. No result proves full room history, human identity, useful contribution authority, independent demand, payment, FLOP ownership or reward eligibility.

The exact input SHA-256 is computed before normalization. The input limit is 12 MiB, 100,000 records and 64 KiB per line. Numeric nonces are parsed without JavaScript floating-point rounding; duplicate JSON members are rejected. The verifier identity, check profile, implementation digest and pinned Technocore source ref are in the artifact. Repeating the same exact bytes under the same verifier/profile has the same workload ID, independent of room/generation context; the latter can change the verdict but not mint a new work unit.

The public-safe artifact defaults to a **redacted room**, contains no transcript bytes or local path, and needs separately supplied original bytes and room for third-party recomputation. Review the downloaded artifact before sharing. The existing Flight Record container renders this as `LOCAL_VALIDATION` computation with **no** `SIGNED`, `SUBMITTED`, `ACK_RECEIVED` or `OBSERVED_PUBLIC` transport states. W1 has no publish or sign-result control. Any optional signed/public result is a separate W2 design and authorization step.

The [implementation addendum](WORKLOAD_W1_CONTRACT_ADDENDUM.md) records the reviewed decisions that override conflicting discovery-report details. The previous reports remain outside this repository for review history.
