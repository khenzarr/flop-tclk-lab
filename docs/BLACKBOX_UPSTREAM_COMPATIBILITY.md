## Why the fingerprints rotate on eight otherwise-identical fixtures

A Blackbox replay fingerprint binds the upstream commit by design — that is the
whole point of provenance. Changing the pin changes every fingerprint even when
each step's outcome, status and state digest are unchanged. The probe therefore
compares *step outcomes* separately from *fingerprints*, and rows where only the
fingerprint moved are labelled `EXPECTED_PROVENANCE`, not a regression. Eight of
nine fixtures are in that class: same accept/reject decisions, same statuses,
same terminal state, same per-step state digests.

## The one real divergence

`fixture:normal-refund`, step 2 (`lock`):

| | Old pin | Current head |
|---|---|---|
| `ok` | `true` | `false` |
| `reason` | `null` | `refund window is already open` |
| `statusAfter` | `locked` | `accepted` |

Step 3 (`refund`) then fails as a consequence (`refund in status accepted`), and
the terminal state becomes `accepted` instead of `refunded`. 17 field-level
differences, all downstream of the one flipped decision.

Cause: upstream `103a1b9` (#42) added a guard so `applyFrame` rejects `lock`
when `nowMs >= refundAfterMs`. Our fixture authored the lock with an
already-open refund window — the old pin permitted it, current head does not.

Classification: this is **not** a regression in upstream and **not** a wire
break. It is upstream getting stricter in the fail-closed direction, and our
fixture was relying on the previously permissive behaviour. The fixture is the
thing that is wrong.

The probe attributes this explicitly as `deadlineAttributedDivergences`, so the
divergence is accounted for rather than merely observed. `unexplainedSurfaces` is
empty — nothing diverged that we cannot name a cause for.

## Repin decision

Not repinning in Phase 3A. Reasons:

1. `fixture:normal-refund` is part of the accepted Phase 2/2.1 evidence set.
   Repinning would rewrite an accepted terminal state from `refunded` to
   `accepted` inside the same commit that ships the Airlock, mixing two
   unrelated truth changes.
2. The correct fix is to re-author the fixture's lock to a lawful time so it
   exercises `refunded` under both trees — a fixture-semantics change that
   deserves its own reviewable step.
3. Nothing in Phase 3A needs current head. The Airlock is upstream-version-aware
   but upstream-version-agnostic: it records whichever SHA prepared the bytes and
   refuses to verify a response across a pin change.

Recommended follow-up (own commit): re-author `normal-refund` to a lawful lock
time, confirm both trees reach `refunded`, then repin and regenerate
fingerprints as a deliberate provenance rotation.

**Phase 3A.1 outcome of that follow-up:** the re-authoring is done and both trees reach `refunded`
(`docs/PHASE3A1_FIXTURE_MIGRATION.md`). The re-pin was still not taken, for a new reason rather
than this one: upstream moved five further commits to `d48e873`, four of which change
protocol-observable behaviour this repository has never probed (decode caps, published-schema
validity, hex rejection, accept-path refusals). Adopting them would import unexamined semantics
and rotate every fingerprint in one step. The pin stays at `81a8346` until those commits get their
own drift pass.

## What this matrix does not prove

- It does not prove current head is correct, only that it agrees with the old pin
  everywhere except one attributed guard.
- It does not exercise the new transcript-record path, the heartbeat frame, or
  the rail registry — those are new surfaces with no old-pin counterpart to
  compare against.
- It says nothing about live venue behaviour. No network call was made.
